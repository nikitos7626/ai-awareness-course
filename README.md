# Образовательный курс: «Как работать с AI осознанно»

Интерактивная образовательная веб-страница для сотрудников компаний без технического образования. Обучает осознанному переходу от наивных чатов к надежным рабочим процессам: формулированию плотного контекста, выбору моделей, созданию скиллов, безопасному использованию MCP и двухмодельной верификации.

Проект разработан на базе дизайн-системы **Soft Media Group (SMG)**.

---

## Быстрый запуск

### Требования
- Node.js 18+ (протестировано на Node.js v24.19.0)
- npm 9+ (протестировано на npm 11.17.0)

### Установка и локальный запуск
```bash
# 1. Установка зависимостей
npm install

# 2. Запуск локального сервера разработки
npm run dev
# Страница откроется по адресу: http://localhost:5173
```

### Запуск тестов и сборки
```bash
# Проверка типов и production-сборка
npm run build

# Запуск модульных и интеграционных тестов (13 тестов Vitest)
npm test

# Запуск E2E тестов в реальном браузере Chromium (2 сценария Playwright: Desktop + Mobile 360px)
npm run test:e2e
```

### Структура и назначение тестов (`tests/`)
В проекте оставлен минимально достаточный набор автотестов (4 файла) без дублирующих аудиторских сьютов:

- `tests/unit/useCourseProgress.test.ts` — модульные тесты хука прогресса (`6` тестов): проверяют расчёт процента прохождения, сохранение и восстановление из `localStorage`, устойчивость к повреждённому JSON и полный сброс прогресса.
- `tests/unit/QuizWidget.test.tsx` — компонентные тесты интерактивного квиза (`4` теста): проверяют сценарий неверного ответа, отображение объяснения, повторную попытку, выбор верного ответа и доступность (`aria-live`).
- `tests/unit/App.test.tsx` — интеграционные тесты корневой страницы (`3` теста): проверяют рендер модулей, первоисточников и диалог подтверждения сброса («Начать заново» → «Да» / «Нет»).
- `tests/e2e/course.spec.ts` — сквозные браузерные тесты Playwright (`2` сценария): проверяют полный пользовательский путь на десктопе (изучение темы → квиз → перезагрузка страницы → сброс) и адаптивность на мобильном экране `360px` (отсутствие горизонтального скролла и работу мобильного меню).

## Стек технологий и архитектура

- **Фреймворк:** React 19 + TypeScript 5
- **Сборщик:** Vite 8 (production-сборка за ~120 мс)
- **Стилизация:** Токены дизайн-системы SMG (CSS Custom Properties), 100% локальные лицензионные шрифты TT Norms Pro и Roboto Flex (без внешних CDN).
- **Тестирование:** Vitest + React Testing Library (Unit/Integration) + Playwright (E2E).
- **Хранение состояния:** Кастомный React-хук `useCourseProgress` с синхронизацией в `localStorage` и безопасным `try/catch` fallback'ом (защита от приватного режима Safari / incognito).

## Архитектура курса (Покрытие 8 обязательных тем ТЗ)

Курс разбит на 3 логических модуля, выстроенных по принципу «от простого к сложному»:

### Модуль 1: Постановка задачи и выбор модели
- **Тема 1. Контекст задачи:** формула плотного контекста Р-З-О-Ф (Роль — Задача — Ограничения — Формат); аналогия с папкой нового сотрудника; деградация контекста при длительных тредах; гигиена чистых сессий.
- **Тема 4. Различия моделей:** каскадный выбор моделей; быстрые и экономичные модели (Flash / Haiku / Luna) для сортировки vs флагманы (Pro / Sonnet / Sol) vs reasoning-модели (o-серия / R1 / Fable) для математики и логики.
- **Тема 5. Типы задач и бенчмарки:** Chatbot Arena (бывш. LMSYS) как слепая дегустация; специализированные тесты (SWE-bench, GPQA); почему слепая вера в абстрактный рейтинг опасна и как собрать внутренний «золотой набор» из 3–5 задач компании.
- **Интерактивный кейс 1:** Анализ 50-страничного договора поставки в отделе закупок (разбор ошибок захламленного чата и постраничного разрыва; выбор чистой сессии модели с окном 200k+ токенов и табличным выводом).

### Модуль 2: Контроль качества: планирование и двухмодельный подход
- **Тема 7. Планирование и ревью плана:** принцип «сначала чертеж, потом стройка»; инструкция «сначала предложи план, не пиши текст»; управление неявными допущениями (Assumptions).
- **Тема 6. Проверка результата:** предвзятость подтверждения (self-bias) модели в том же чате; методика двухмодельной перекрестной проверки в чистой сессии; четкое разграничение ответственности: что может перепроверить AI, а какие цифры и факты обязан верифицировать человек.
- **Интерактивный кейс 2:** Подготовка аналитической записки для совета директоров с непроверенной цифрой роста рынка 34.2% (защита от правдоподобных галлюцинаций через двухмодельный аудит аргументации и ручной фактчекинг первоисточников).

### Модуль 3: Автономия: от чата к агентам
- **Тема 2. Скиллы (Skills):** отличие разового запроса от регламента; обеспечение повторяемости (кулинарный рецепт ресторана); практический шаблон скилла отдела «Саммари клиентской претензии».
- **Тема 3. MCP (Model Context Protocol):** зачем агенту доступ к базам и файлам; аналогия с разъемом USB-C; принцип наименьших привилегий (Least Privilege / гостевой пропуск); правило «чтение — автоматом, запись и удаление — только по подтверждению человека».
- **Тема 8. Харнесы (Harnesses) / обвязки агентов:** аналогия с конвейером автозавода; блокнот состояния (scratchpad); предохранители и условия остановки («3 неудачные попытки — зови человека»).
- **Интерактивный кейс 3:** Настройка AI-агента для регулярной выгрузки зависших сделок из CRM в Telegram (разграничение прав на Read-only, лимиты выборки и обязательное предварительное превью).

### Раздел достоверности и первоисточников
В курс включен блок из 4 проверенных официальных источников:
1. *Model Context Protocol (MCP) — Спецификация и архитектура* (`modelcontextprotocol.io`).
2. *Anthropic Prompt Engineering Guide* (`docs.anthropic.com`).
3. *Hugging Face Open LLM — Документация и модели* (`huggingface.co`).
4. *Chatbot Arena Leaderboard* (`lmarena.ai`).

## Доступность (A11y, WCAG 2.1 AA) и мобильный UX

- **Клавиатурная навигация:** Полный сценарий (сквозной переход по оглавлению, отметка темы как изученной, выбор вариантов ответа в квизе, повтор попытки, сброс) доступен с клавиатуры (`Tab`, `Space`, `Enter`).
- **Skip-Link:** Реализована ссылка `.skip-to-content-link` для быстрого перехода к учебному материалу при клавиатурном фокусе.
- **Фокус-ринги:** В соответствии с требованиями WCAG 2.1 AA добавлен двухслойный высококонтрастный фокус:
  `box-shadow: 0 0 0 2px #FFFFFF, 0 0 0 4px #6228FF`.
- **Семантика и скринридеры:** Использованы семантические теги (`<main>`, `<aside>`, `<article>`), WAI-ARIA атрибуты (`role="radiogroup"`, `role="radio"`, `role="progressbar"`), а блок объяснений квиза снабжен `aria-live="polite"`.
- **Адаптивность от 360px:** Страница протестирована на вьюпорте `360×800` через Playwright. Горизонтальный скролл полностью исключен (`scrollWidth <= innerWidth`), кнопки и элементы ввода имеют высоту от 44px (Touch Target compliance). На экранах `<1024px` навигация трансформируется в мобильный Off-canvas Drawer.

## Процесс работы с AI и результаты двух ревью (AI Workflow)

В соответствии с требованиями задания разработка велась по строгому трехэтапному инженерному процессу с фиксацией промежуточных ревью:

### 1. Этап 1: Первичный план и Review 1 (в чистой сессии)
- **Что было на входе:** Первичный план распределения тем и архитектуры.
- **Что выявило ревью:**
  1. Разрыв методологической связки «Планирование (Тема 7) — Проверка (Тема 6)», которые были разнесены по разным модулям.
  2. Перегрузка исходного Модуля 3 (4 темы из 8).
  3. Риск использования слайдовых размеров шрифтов (26–30px) из исходных презентационных файлов SMG.
  4. Недостаточный контраст базового фокус-ринга (12% альфа) и отсутствие семантического токена успеха (`--smg-success`).
- **Что изменили по итогам Review 1:**
  - Перегруппировали модули в прозрачную последовательность: «1. Постановка и выбор модели» → «2. Контроль качества и ревью» → «3. Автономия и агенты».
  - Зафиксировали адаптацию компонентов под Web UI токены (`15–16px` базовый текст).
  - Добавили в систему токен `--smg-success: #10B981` и контрастный фокус `var(--smg-focus-ring-a11y)`.
  - Заменили абстрактные вопросы квизов на реалистичные офисные кейсы.

### 2. Этап 2: Имплементация с AI-агентом
- Кодовая база снабжена инструкциями для агентов в файле `AGENTS.md`.
- Созданы переиспользуемые модульные компоненты на TypeScript.
- Реализовано персистентное состояние и автотесты.

### 3. Этап 3: Финальное QA & Design System Review 2 (в чистой сессии)
- **Что проверялось:** Полная кодовая база, стили, поведение на 360px, верстка, автотесты и соответствие design.md.
- **Выявленные замечания и выполненные доработки:**
  1. *Устранение эмодзи:* В строгом соответствии с design.md («В комплекте есть линейные иконки... Не заменяйте их эмодзи») все эмодзи были полностью заменены на векторные компоненты `<Icon>` из библиотеки SMG (`Award03`, `CheckVerified02`, `BarChart08`, `ThumbsUp`, `File05`, `ArrowNarrowRight`).
  2. *Очистка шаблона:* Удалены неиспользуемые файлы сборщика Vite (`App.css`, `react.svg`, `vite.svg`, `hero.png`).
  3. *Улучшение a11y:* Правило `:focus` уточнено до `:focus:not(:focus-visible)` для сохранения нативного фокуса в legacy-окружениях без потери кастомного кольца.
- **Результаты проверки:**
  - `npm run build`: успешно (130 мс).
  - `npm test`: 13 из 13 тестов пройдены (useCourseProgress, QuizWidget, App).
  - `npm run test:e2e`: 2 из 2 сквозных сценария Playwright пройдены (десктопный цикл и мобильный 360px без горизонтального скролла).
  - Подтверждено: нулевое использование сервисного синего цвета `--smg-info-500` в основных элементах бренда, 100% локальные шрифты, корректная работа клавиатурного фокуса, отсутствие сторонних эмодзи.
- **Итоговый вердикт ревьюера:** **PASS** — проект полностью готов к сдаче.

## Принятые допущения и границы MVP

### Что включено в MVP:
- Все 8 обязательных тем ТЗ, адаптированных для сотрудников без технического образования.
- 3 интерактивных бизнес-кейса с моментальным разбором, объяснением ошибок и кнопкой повтора.
- Полноценная навигация: десктопный сайдбар со статусами тем и мобильный off-canvas drawer.
- Полная поддержка клавиатурной доступности и WCAG 2.1 AA.
- Сохранение прогресса в `localStorage` с безопасным диалогом сброса.
- Блок официальной документации с проверенными первоисточниками.
- Набор модульных, интеграционных и сквозных E2E-тестов (13 тестов Vitest + 2 E2E сценария Playwright = **15 автотестов**).

### Что вынесено за рамки MVP:
- Серверная авторизация / backend.
- Тяжелое мультимедиа / видеофайлы.

### Что улучшил бы в следующей итерации:
- Более качественная вёрстка с более крупным текстом и усиленной визуальной иерархией для ещё более комфортного чтения уроков.
- Более понятная подборка документации и первоисточников для нетехнических пользователей — с краткими пояснениями на русском языке и подсказками, что именно в них полезно посмотреть.
- Упрощение профессионального сленга и англицизмов в текстах уроков (замена на более простые формулировки или интерактивные подсказки/ссылки с расшифровкой терминов).
